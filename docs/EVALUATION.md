# LawTutor 검색 품질 평가 보고서

## 1. 평가 목적

LawTutor MCP 서버는 RAG(Retrieval-Augmented Generation) 파이프라인의 **검색(Retrieval)** 부분만 담당합니다. LLM 추론은 Claude Pro가 하므로, 본 서버의 핵심 품질은 **"사용자 질문에 대해 정확한 법령/판례를 찾아 반환하는가"**입니다.

이를 정량적으로 측정하기 위해 60건의 평가셋을 구축하고, Recall@5, MRR, 메타데이터 무결성 3가지 지표로 평가했습니다.

### 2.3 정답(Expected) 설정 방법

평가의 신뢰도를 위해, 정답을 설정하는 방법을 도구 유형에 따라 구분했습니다.

**법령 검색 (`search_law`)**: 행정절차법, 행정심판법, 대한민국헌법의 조문을 대상으로, 질문에 해당하는 정답 조문을 사전에 수작업으로 지정했습니다. 예: "행정절차법상 처분의 사전통지에 대해 알려줘" → 정답: `행정절차법 제21조`.

**정확 조회 (`fetch_article_by_number`, `fetch_case_by_number`)**: DB에 실제 존재하는 조문번호/사건번호를 Qdrant에서 확인한 뒤 정답으로 지정했습니다. 정확 매칭이므로 검색 정확도가 아닌 데이터 적재 무결성을 확인합니다.

**판례/결정례 검색 (`search_precedent`, `search_constitutional_decision`)**: 주제별 쿼리(예: "과잉금지원칙에 관한 헌재 결정")를 실제로 실행하고, 반환된 결과가 주제에 부합하는지 수작업으로 검증한 뒤, 검증된 사건번호 2~3개를 정답으로 설정했습니다. 이 중 1건이라도 top-5에 포함되면 해당 항목을 정답으로 인정합니다.

**법령해석례 검색 (`search_legal_interpretation`)**: 해석례는 특정 사건번호를 기대하기 어려우므로, 정답을 비워두고 메타데이터 무결성만 평가했습니다.

### 2.4 난이도 기준

| 난이도 | 기준 |
|--------|------|
| 하 | 정확 조회(조문번호/사건번호 명시) 또는 단일 조문이 명확히 대응되는 질문 |
| 중 | 의미 검색이 필요하며, 관련 조문/판례가 여러 개 존재하는 질문 |
| 상 | 간접적 표현 사용, 여러 법령에 걸친 개념, 또는 제목과 검색어가 불일치하는 질문 |

## 3. 평가 메트릭

### 3.1 Recall@5 (재현율)

**정의**: 정답 문서가 검색 결과 상위 5건에 포함되어 있는 비율.

```
Recall@5 = (top-5에서 찾은 정답 수) / (전체 정답 수)
```

예시:
- 정답이 `["행정절차법 제21조"]`이고, 검색 결과 5건 중 제21조가 있으면 → Recall = 1.0
- 정답이 `["98두4061", "2005두6539", "2003두12899"]`이고, 이 중 2건이 top-5에 있으면 → Recall = 2/3 = 0.67

**왜 중요한가**: RAG 시스템에서 정답이 검색 결과에 빠지면, LLM이 아무리 똑똑해도 올바른 답변을 생성할 수 없습니다. Recall은 검색 품질의 가장 기본적인 지표입니다.

### 3.2 MRR (Mean Reciprocal Rank, 평균 역순위)

**정의**: 첫 번째 정답이 검색 결과에서 몇 번째에 나타나는지의 역수를 전체 항목에 대해 평균.

```
RR = 1 / (첫 정답의 순위)
MRR = 전체 항목의 RR 평균
```

예시:
- 정답이 1번째에 나타남 → RR = 1/1 = 1.0
- 정답이 3번째에 나타남 → RR = 1/3 = 0.33
- 정답이 top-5에 없음 → RR = 0.0

**왜 중요한가**: 정답이 1등인지 5등인지의 차이를 측정합니다. 다만 본 시스템에서는 Claude Pro가 top-5 결과를 모두 읽고 종합하므로, Recall보다 상대적으로 덜 중요합니다.

### 3.3 메타데이터 무결성

**정의**: 검색 결과에 필수 메타데이터 필드(법령명, 조문번호, 시행일, 사건번호 등)가 모두 존재하는 비율.

```
무결성 = (필수 필드가 모두 있는 결과 수) / (전체 결과 수)
```

**왜 중요한가**: Claude Pro가 "행정절차법 제21조에 따르면..."이라고 정확히 인용하려면, 검색 결과에 법령명·조문번호 등의 메타데이터가 반드시 포함되어 있어야 합니다.

**참고**: 이 지표는 검색 알고리즘이 아닌 데이터 파이프라인(수집→파싱→청킹→저장)의 품질을 반영합니다. 데이터가 올바르게 적재되었으면 항상 1.0이 나옵니다.

## 5. 평가 인프라

### 5.1 파일 구조

```
data/eval/
  eval_set_v1.jsonl       # 초기 평가셋 (10건, 파일럿)
  eval_set_v2.jsonl       # 확장 평가셋 (60건, 본 보고서 기준)
data/eval_results/
  20260517_183004.json    # 평가 결과 (타임스탬프별 저장)

src/lawtutor/evaluation/
  eval_set.py             # EvalItem 모델 및 JSONL 로더
  metrics.py              # Recall@K, MRR, 메타데이터 무결성 계산

scripts/
  run_eval.py             # 평가 실행 스크립트
```

### 5.2 평가 실행 방법

```bash
# 기본 실행 (top_k=5)
uv run python scripts/run_eval.py --eval-set data/eval/eval_set_v2.jsonl

# top_k 변경
uv run python scripts/run_eval.py --eval-set data/eval/eval_set_v2.jsonl --top-k 10

# 이전 결과와 비교
uv run python scripts/run_eval.py --eval-set data/eval/eval_set_v2.jsonl \
  --compare-with data/eval_results/20260517_183004.json
```

### 5.3 평가셋 항목 형식

```json
{
  "question": "행정절차법상 처분의 사전통지에 대해 알려줘",
  "category": "행정법",
  "difficulty": "하",
  "tool": "search_law",
  "expected_articles": ["행정절차법 제21조"],
  "expected_case_nos": []
}
```

### 5.4 평가 파이프라인

```
평가셋 (JSONL)
    ↓
run_eval.py가 각 항목을 순회
    ↓
항목의 tool에 맞는 Retriever 메서드 호출
    ↓
검색 결과와 expected를 비교하여 메트릭 산출
    ↓
항목별 결과 + 집계 결과를 JSON으로 저장
```

## 7. 한계 및 향후 개선

### 7.1 평가셋의 한계

- 법령 검색 29건은 행정절차법·행정심판법·대한민국헌법 3개 법령에 집중되어 있음. 5,500+ 법령 전체를 대표하지는 않음
- 법령해석례 평가 항목이 3건으로 적음 (정답 지정이 어려워 메타데이터 무결성만 측정)
- 판례/결정례의 expected는 실제 검색 결과를 기반으로 설정했으므로, 독립적 검증이 아닌 자기검증(self-validation)의 성격이 있음

### 7.2 확인된 약점

- **헌법 조문 검색**: 대한민국헌법은 조문 제목이 없어, 개념 검색 시 같은 키워드를 제목에 포함한 다른 법률이 우선 매칭됨
- **동의어 불일치**: "재결의 종류"(사용자 표현) vs "재결의 구분"(실제 조문 제목) 같은 유의어 차이를 아직 커버하지 못하는 경우 있음

### 7.3 개선 방향

1. 헌법 조문에 인위적 제목 메타데이터 추가 (예: 제11조 → "평등권/평등의 원칙")
2. `LEGAL_SYNONYMS` 동의어 사전 확장 ("종류"↔"구분", "규정"↔"조항" 등)
3. 평가셋을 100건 이상으로 확대하고, 5,500+ 법령 중 더 다양한 법령을 포함
4. 판례/결정례 평가에 대해 법학 전문가의 독립적 검증 추가

# LawTutor MCP 프로젝트 설명서 (자소서 작성용)

> 이 문서는 자기소개서 작성 시 프로젝트를 설명하기 위한 참고 자료입니다.
> Claude AI 웹에서 자소서를 작성할 때 이 문서를 함께 제공하면, 프로젝트의 기술적 깊이와 의사결정 과정을 정확하게 반영할 수 있습니다.

---

## 1. 프로젝트 한 줄 요약

**한국 법령·판례 94만 건을 벡터 검색으로 제공하는 MCP 서버를 개인 PC에서 셀프 호스팅하여, Claude AI가 1차 출처에 근거한 법률 답변을 생성하도록 한 RAG 시스템.**

---

## 2. 프로젝트 배경과 문제 인식

### 2.1 해결하려는 문제
7급 공무원시험(행정직) 수험 준비 중, 범용 LLM(Claude, ChatGPT 등)에 법령/판례 질문을 하면 다음과 같은 **할루시네이션**이 빈번하게 발생:
- 존재하지 않는 조문번호 생성 (예: 행정절차법 제30조의5 — 실재하지 않음)
- 존재하지 않는 사건번호 생성 (예: 대법원 2018두12345 — 허구)
- 폐지·개정된 조문을 현행으로 답변
- 헌재결정례를 대법원 판례로 혼동

수험생이 이를 신뢰하면 잘못된 지식이 굳어져 시험에서 직접적인 감점 요인이 된다.

### 2.2 해결 방향
국가법령정보센터(open.law.go.kr) OPEN API에서 **1차 출처 데이터를 전량 수집**하고, 이를 벡터 DB에 인덱싱한 뒤 **MCP(Model Context Protocol) 서버**로 검색 도구를 제공한다. 사용자가 Claude Pro에서 이 MCP 서버를 연결하면, Claude가 질문을 받았을 때 자동으로 1차 출처를 검색하고 근거에 기반한 답변을 생성한다.

### 2.3 왜 MCP인가 (설계 의사결정)
- **비용 최적화**: Claude Pro 정액제($20/월) 안에서 LLM 추론 처리. 별도 API 토큰 비용 0원.
- **책임 분리**: 검색은 본 서버, 추론은 Claude Pro. 각자 잘하는 일에 집중하는 아키텍처.
- **표준 프로토콜**: MCP는 2024~2025년 새로 표준화된 LLM 도구 연동 프로토콜. Claude Desktop, Cursor, VS Code 등 다양한 클라이언트에서 동일하게 사용 가능.

## 3. 시스템 아키텍처

```
[사용자] → Claude.ai 웹에서 자연어 질문
    ↓
[Claude Pro (LLM)] → 질문 분석, MCP 도구 호출 결정
    ↓ HTTPS (MCP Streamable HTTP)
[Cloudflare Edge] → DDoS/WAF 보호, TLS 종단
    ↓ Cloudflare Tunnel (아웃바운드 전용 영구 연결)
[개인 데스크탑 PC (24/7 운영)]
    ├─ cloudflared (터널 데몬)
    ├─ FastAPI + MCP Server (Docker 컨테이너)
    ├─ Qdrant 벡터 DB (Docker 컨테이너)
    └─ BGE-M3 임베딩 모델 (메모리 로드)
```

### 핵심 설계 포인트
1. **LLM은 서버에 없다** — 서버는 검색 도구만 노출, 추론은 Claude Pro가 전담
2. **Cloudflare Tunnel로 외부 노출** — 라우터 포트포워딩 없이, 공인 IP 노출 없이, HTTPS/DDoS 보호 자동 적용
3. **Docker Compose로 3개 서비스 통합 관리** — app, qdrant, cloudflared
4. **월 운영비 도메인비(~1만원) + 전기세 외 0원**

## 4. 데이터 파이프라인

### 4.1 데이터 소스
**국가법령정보센터 OPEN API 단일 소스.** 외부 사이트 크롤링은 이용약관 위반 및 데이터베이스권 침해 리스크가 있어 사용하지 않음.

### 4.2 수집 규모 (최종 수치)
| 컬렉션 | 벡터 수 (points) | 원본 건수 | 설명 |
|---|---|---|---|
| laws (법령) | 240,695 | 5,583개 법령 | 행정법/헌법 관련 법령 + 시행령/시행규칙 |
| precedents (판례) | 579,012 | 122,352건 | 대법원 판례 (API 제공 전량) |
| decisions (헌재결정례) | 99,394 | 37,826건 | 헌법재판소 결정례 전량 |
| interpretations (법령해석례) | 26,839 | 8,708건 | 법제처 유권해석례 |
| **합계** | **945,940** | **174,469건** | |

### 4.3 파이프라인 단계
```
[국가법령정보센터 API] → XML 응답
    ↓ Collectors (httpx 비동기 + tenacity 재시도)
[data/raw/] → 원본 XML 보존 (파싱 실패 시 재처리 가능)
    ↓ Parsers (XML → Pydantic 모델)
[data/parsed/] → 정형 JSON
    ↓ Chunkers (도메인 특화 청킹)
[청크 생성] → 법령은 조(條) 단위, 판례는 섹션 단위
    ↓ BGE-M3 Embedder (1024차원 벡터)
[Qdrant] → 4개 컬렉션에 upsert
```

### 4.4 도메인 특화 청킹 전략 (차별점)
범용 텍스트 청킹이 아닌 법률 문서 구조에 맞춘 전략:
- **법령**: 조(Article) 단위 청킹. 800자 초과 시 항(Paragraph) 단위 분할. 조문 구조(항·호·목) 보존.
- **판례**: 섹션 단위 분할 — 판시사항, 판결요지, 판례내용을 별도 청크로. 동일 사건번호로 연결.
- **헌재결정례**: 판례와 동일 전략.
- **법령해석례**: 질의요지 + 회답 + 이유를 하나의 청크로.

### 4.5 시행일자 기반 현행 법령 필터링 (차별점)
한국 법령은 개정이 잦다. 모든 청크에 `effective_date`(시행일), `is_active`(현행 여부) 메타데이터를 부여하고, 검색 시 기본 필터로 `is_active=True`를 적용하여 **폐지/개정 조문이 현행으로 잘못 반환되는 문제를 원천 차단**.

## 5. MCP 서버 (6개 검색 도구)

### 5.1 제공 도구

| # | 도구명 | 기능 | 검색 방식 |
|---|---|---|---|
| 1 | `search_law` | 행정법/헌법 법령 조문 의미 검색 | 벡터 유사도 + 메타데이터 필터 |
| 2 | `search_precedent` | 대법원 판례 검색 | 벡터 유사도 + 법원 필터 |
| 3 | `search_constitutional_decision` | 헌법재판소 결정례 검색 | 벡터 유사도 + 사건유형 필터 |
| 4 | `search_legal_interpretation` | 법제처 유권해석례 검색 | 벡터 유사도 |
| 5 | `fetch_article_by_number` | 법령명+조문번호로 정확한 조문 직접 조회 | 메타데이터 exact match |
| 6 | `fetch_case_by_number` | 사건번호로 판례/결정례 직접 조회 | 메타데이터 exact match |

### 5.2 도구 설명 설계 (LLM이 올바른 도구를 선택하도록)
MCP tool의 description은 **LLM이 읽고 어떤 도구를 호출할지 결정하는 기준**이다. 각 도구마다:
- 어떤 상황에서 사용해야 하는지 (트리거 시나리오)
- 다른 도구와의 구분 기준
- 입력 인자 가이드
를 상세하게 작성하여 Claude가 사용자 질문 의도에 맞는 도구를 정확히 선택하도록 함.

### 5.3 API 폴백 (하이브리드 검색)
벡터 검색 결과가 부족할 때, 국가법령정보센터 API를 실시간으로 호출하여 보충하는 폴백 메커니즘 구현. 벡터 DB에 없는 데이터도 놓치지 않도록 이중 안전망 확보.

## 6. 기술 스택 (선정 근거 포함)

| 영역 | 기술 | 선정 근거 |
|---|---|---|
| 언어 | Python 3.11+ | MCP SDK 공식 지원, 비동기 생태계 |
| MCP SDK | `mcp` (공식 Python SDK) | Streamable HTTP transport 지원 |
| 웹 프레임워크 | FastAPI + uvicorn | 비동기 네이티브, MCP 마운트 용이 |
| 벡터 DB | Qdrant (Docker) | 메타데이터 필터링 우수, 셀프 호스팅 무료 |
| 임베딩 | BGE-M3 (1024차원) | 한국어 성능 최상위급, 다국어 지원 |
| 데이터 검증 | Pydantic v2 | 타입 안전성, 직렬화/역직렬화 자동 |
| HTTP 클라이언트 | httpx (비동기) | async/await 네이티브 지원 |
| 재시도 | tenacity | API 호출 실패 시 지수 백오프 재시도 |
| Rate limiting | slowapi | IP 기반 분당 60 요청 제한 |
| 컨테이너 | Docker Compose | 3개 서비스(app, qdrant, cloudflared) 통합 관리 |
| 외부 노출 | Cloudflare Tunnel | 포트포워딩 없이 HTTPS + DDoS 보호 |
| 인증 | Bearer Token (32바이트+) | MCP Custom Connector 호환 |

## 7. 배포 및 운영

### 7.1 인프라 구성
- **호스트**: 개인 데스크탑 PC (Windows 11, RAM 16GB+)
- **컨테이너**: Docker Desktop + Docker Compose
- **외부 노출**: Cloudflare Tunnel (아웃바운드 전용 → 공인 IP 미노출)
- **도메인**: lawtutor.dev (Cloudflare에서 관리)
- **HTTPS**: Cloudflare Edge에서 자동 TLS 종단 (자체 인증서 불필요)

### 7.2 보안 설계
- Cloudflare Edge에서 DDoS 보호 + WAF 자동 적용
- 라우터 포트포워딩 절대 금지 (Cloudflare Tunnel만 사용)
- Bearer Token 인증 (32바이트 이상 랜덤)
- IP 기반 Rate limiting (분당 60)
- Docker 컨테이너 격리
- API 키·토큰은 `.env`로만 관리, git 커밋 금지

### 7.3 24/7 안정성
| 장애 시나리오 | 자동 대응 |
|---|---|
| 인터넷 일시 단절 | cloudflared 자동 재연결 |
| PC 재부팅 | Docker Desktop 자동 시작 + `restart: unless-stopped` |
| Cloudflare 엣지 장애 | 다른 엣지 노드로 자동 전환 |

### 7.4 리소스 사용량
| 컴포넌트 | RAM |
|---|---|
| FastAPI 앱 | ~500MB |
| Qdrant (94만 벡터) | 1~2GB |
| BGE-M3 모델 | 2~3GB |
| cloudflared | ~100MB |
| **합계** | **~6GB** |

## 9. 이 프로젝트의 기술적 차별점

### 9.1 vs 일반 RAG 프로젝트
| 일반 RAG | LawTutor MCP |
|---|---|
| PDF/웹 크롤링 → 범용 청킹 | 정부 공식 API → 도메인 특화 청킹 (조 단위, 섹션 단위) |
| LLM API 호출 포함 | LLM 없음. 검색만 제공, 추론은 클라이언트에 위임 |
| 웹 UI 직접 구현 | MCP 표준 프로토콜로 도구만 노출 → 어떤 MCP 클라이언트에서든 사용 |
| 클라우드 배포 | 개인 PC + Cloudflare Tunnel 셀프 호스팅 (월 운영비 ~0원) |
| 시행일자 고려 없음 | `is_active` 필터로 현행 법령만 우선 반환 |

### 9.2 핵심 어필 포인트 (자소서 활용 시)
1. **MCP 서버 구축 경험** — 2024~2025년 새로 표준화된 LLM 도구 연동 프로토콜. 아직 실제 구축 경험자가 매우 적은 영역.
2. **94만 벡터 규모의 실데이터 RAG** — 토이 프로젝트 수준이 아닌, 국가법령정보센터 API 제공 전량을 수집·인덱싱.
3. **도메인 지식 반영 설계** — 법률 문서의 구조(조·항·호, 판시사항·판결요지·이유)를 이해하고 이에 맞춘 청킹 전략 설계.
4. **비용 0원 아키텍처** — 개인 PC + Cloudflare Tunnel로 클라우드 비용 없이 프로덕션 수준 배포. 비용/보안 트레이드오프 사고력.
5. **책임 분리 아키텍처** — "검색 서버는 검색만, LLM은 추론만"이라는 명확한 단일 책임 원칙 적용.
6. **실사용 가능한 완성도** — Claude.ai에서 Custom Connector로 연결하여 실제 학습에 활용 중.

## 10. 기술적 도전과 해결

### 10.1 판례 데이터 수집 한계 파악
- API 목록에는 172,340건이 표시되나, 실제 본문 요청 시 49,456건은 "일치하는 판례가 없습니다" 에러 반환.
- 원인 분석: 삭제/비공개 판례가 목록에는 남아있으나 본문 미제공. 즉 API 제공 전량은 122,838건.
- **시사점**: 외부 데이터 소스의 한계를 인지하고, 오류 원인을 추적하여 "파싱 버그인지 vs API 한계인지"를 구분한 문제 해결 과정.

### 10.2 도메인 특화 청킹 설계
- 범용 텍스트 스플리터(langchain 등)는 법률 문서의 조·항·호 구조를 무시하고 잘라, 맥락이 깨지는 문제 발생.
- 법령은 조(條) 단위, 판례는 판시사항/판결요지/이유 섹션 단위로 분할하는 커스텀 청킹 로직 설계.
- 각 청크에 원본의 모든 메타데이터(법령명, 조문번호, 시행일, 사건번호 등)를 보존하여 출처 추적 가능.

### 10.3 개인 PC에서의 프로덕션 배포
- 라우터 포트포워딩 → 공인 IP 노출, 보안 리스크 → Cloudflare Tunnel 채택.
- Docker Compose로 3개 서비스 통합 관리, `restart: unless-stopped`로 자동 복구.
- RAM 6GB 수준에서 94만 벡터 검색 서비스 안정 운영.

### 10.4 LLM 도구 선택 최적화
- MCP tool description을 단순 설명이 아닌, "언제 이 도구를 사용해야 하는가"를 Claude가 판단할 수 있도록 트리거 시나리오, 키워드 목록, 다른 도구와의 구분 기준을 상세하게 작성.
- 이를 통해 사용자가 "처분의 사전통지"를 물었을 때 search_law가, "관련 판례"를 물었을 때 search_precedent가 자동으로 호출되도록 함.

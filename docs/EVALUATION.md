# LawTutor 검색 품질 평가 보고서

## 1. 평가 목적

LawTutor MCP 서버는 RAG(Retrieval-Augmented Generation) 파이프라인의 **검색(Retrieval)** 부분만 담당합니다. LLM 추론은 Claude Pro가 하므로, 본 서버의 핵심 품질은 **"사용자 질문에 대해 정확한 법령/판례를 찾아 반환하는가"**입니다.

이를 정량적으로 측정하기 위해 102건의 평가셋을 구축하고, Recall@5, MRR, 메타데이터 무결성 3가지 지표로 평가했습니다.

---

## 2. 평가 방법론: 독립 검증(Independent Validation)

### 2.1 자기검증의 문제

v2 평가셋(60건)에서는 판례·결정례 항목의 정답(expected)을 **시스템 자체의 검색 결과로부터** 설정했습니다. 즉, 시스템에 쿼리를 먼저 실행하고, 반환된 사건번호가 주제에 부합하는지 확인한 뒤 그것을 정답으로 등록하는 방식이었습니다.

이 접근에는 본질적 한계가 있습니다:

- **순환 논증**: 시스템이 찾아준 결과를 정답으로 삼으면, 시스템이 찾지 못한 중요한 문서가 정답에서 빠집니다. 결과적으로 Recall이 과대평가됩니다.
- **검증 불가**: 제3자가 "이 정답이 정말 해당 주제의 대표 판례인가?"를 독립적으로 확인할 방법이 없습니다.
- **포트폴리오 신뢰도**: 자기검증 기반 Recall 0.94는 숫자는 높지만, 방법론적으로 면접관에게 설득력이 낮습니다.

### 2.2 독립 검증이란

v3 평가셋(102건)에서는 **시스템 외부의 권위 있는 출처**에서 정답을 설정했습니다:

| 출처 | 적용 대상 | 예시 |
|------|-----------|------|
| 법령 원문 (조문번호가 결정적) | 법령 검색 40건, 정확 조회 12건 | "처분의 사전통지" → 행정절차법 제21조 |
| 행정법 교과서·시험 교재 | 판례 검색 20건 | "신뢰보호 원칙" → 98두4061 (대표 판례) |
| 헌법 교과서·시험 교재 | 헌재결정 검색 14건 | "과잉금지원칙" → 92헌가8 (대표 결정) |
| DB 존재 확인 (fetch) | 사건번호 조회 8건 | "84누647" → DB에 존재하는 사건번호 |

**핵심 차이**: 정답을 시스템이 아닌 외부에서 가져오므로, 시스템이 해당 문서를 찾지 못하면 Recall이 정직하게 떨어집니다.

### 2.3 독립 검증의 한계

독립 검증도 완벽하지는 않습니다:

- **교과서 선택 편향**: 특정 교과서가 강조하는 판례가 DB에 다른 형태로 존재할 수 있음
- **사건번호 표기 차이**: 교재의 "98두4061"과 DB의 "97누15418"이 같은 법리의 다른 판례일 수 있음
- **주제 대표성**: "과잉금지원칙 대표 판례"는 하나가 아니라 수십 개이므로, 어떤 것을 정답으로 삼느냐에 따라 결과가 달라짐

이러한 한계에도 불구하고, 자기검증보다 독립 검증이 **방법론적으로 더 정직하고 설득력 있는** 접근입니다.

**헌재결정 검색 (`search_constitutional_decision`, 14건)**: 헌법 주요 논점별로 **교과서에서 대표 결정으로 다루는 사건번호**를 정답으로 설정했습니다. 예: "과잉금지원칙" → 92헌가8, "재산권 침해" → 89헌마214, "양심의 자유" → 2017헌바42.

## 4. 평가 메트릭

### 4.1 Recall@5 (재현율)

**정의**: 정답 문서가 검색 결과 상위 5건에 포함되어 있는 비율.

```
Recall@5 = (top-5에서 찾은 정답 수) / (전체 정답 수)
```

예시:
- 정답이 `["행정절차법 제21조"]`이고, 검색 결과 5건 중 제21조가 있으면 → Recall = 1.0
- 정답이 `["98두4061"]`이고, top-5에 해당 판례가 없으면 → Recall = 0.0

**왜 중요한가**: RAG 시스템에서 정답이 검색 결과에 빠지면, LLM이 아무리 똑똑해도 올바른 답변을 생성할 수 없습니다. Recall은 검색 품질의 가장 기본적인 지표입니다.

### 4.2 MRR (Mean Reciprocal Rank, 평균 역순위)

**정의**: 첫 번째 정답이 검색 결과에서 몇 번째에 나타나는지의 역수를 전체 항목에 대해 평균.

```
RR = 1 / (첫 정답의 순위)
MRR = 전체 항목의 RR 평균
```

예시:
- 정답이 1번째에 나타남 → RR = 1/1 = 1.0
- 정답이 3번째에 나타남 → RR = 1/3 = 0.33
- 정답이 top-5에 없음 → RR = 0.0

**왜 중요한가**: 정답이 1등인지 5등인지의 차이를 측정합니다. 다만 본 시스템에서는 Claude Pro가 top-5 결과를 모두 읽고 종합하므로, Recall보다 상대적으로 덜 중요합니다.

### 4.3 메타데이터 무결성

**정의**: 검색 결과에 필수 메타데이터 필드(법령명, 조문번호, 시행일, 사건번호 등)가 모두 존재하는 비율.

```
무결성 = (필수 필드가 모두 있는 결과 수) / (전체 결과 수)
```

**왜 중요한가**: Claude Pro가 "행정절차법 제21조에 따르면..."이라고 정확히 인용하려면, 검색 결과에 법령명·조문번호 등의 메타데이터가 반드시 포함되어 있어야 합니다.

**참고**: 이 지표는 검색 알고리즘이 아닌 데이터 파이프라인(수집→파싱→청킹→저장)의 품질을 반영합니다. 데이터가 올바르게 적재되었으면 항상 1.0이 나옵니다.

### 5.3 v2→v3 Recall 하락 원인 분석

전체 Recall이 0.94에서 0.75로 하락한 원인은 **판례·결정례 의미 검색**에 집중되어 있습니다.

| 도구 | v2 Recall | v3 Recall | 차이 원인 |
|------|-----------|-----------|-----------|
| `search_law` | 0.897 | 0.900 | 변화 없음 (법령 조문은 결정적이므로) |
| `fetch_*` | 1.000 | 1.000 | 변화 없음 |
| `search_precedent` | 0.958 | **0.400** | v2는 시스템이 찾은 판례가 곧 정답, v3는 교과서 대표 판례가 정답 |
| `search_constitutional_decision` | 1.000 | **0.357** | 동일한 이유 |

판례·결정례 검색의 Recall이 낮은 구조적 이유:

1. **검색 공간의 크기**: 판례 컬렉션 579,012건, 결정례 99,394건 중에서 특정 1건을 top-5에 포함시키는 것은 본질적으로 어려움
2. **의미 검색의 한계**: "과잉금지원칙 판례"라는 쿼리에 의미적으로 관련된 판례가 수십~수백 건 존재하며, 그 중 교과서가 대표로 꼽는 특정 1건이 top-5에 들어올 확률은 낮음
3. **청크 단위 검색**: 판례는 판시사항/판결요지/판례내용 등 섹션 단위로 청킹되어 있어, 같은 판례의 다른 섹션이 top-5를 차지할 수 있음

**이것은 검색 엔진의 결함이라기보다, 의미 검색으로 특정 문서를 찾는 작업의 본질적 어려움입니다.** 사용자가 사건번호를 알면 `fetch_case_by_number`로 100% 정확하게 조회할 수 있습니다.

| 난이도 | n | Recall@5 | MRR |

| 하 | 27 | **1.0000** | 0.9815 |

- **하**: 정확 조회 또는 명확한 법령 검색 → 완벽한 성능

난이도가 올라갈수록 Recall이 떨어지는 것은 예상된 패턴이며, 특히 "상" 난이도에 판례/결정례 의미 검색이 집중되어 있습니다.

## 6. 도구 유형별 성격 분석

평가 결과를 통해, 6개 MCP 도구가 두 가지 뚜렷한 유형으로 나뉘는 것을 확인했습니다.

### 유형 1: 결정적 조회 (Recall = 1.00)

| 도구 | 특성 |
|------|------|
| `fetch_article_by_number` | 법령명+조문번호 → 정확히 1건 반환 |
| `fetch_case_by_number` | 사건번호 → 정확히 1건 반환 |

사용자가 찾을 대상을 정확히 아는 경우 사용. **100% 정확도**.

### 유형 2: 의미 검색 (Recall이 변동)

| 도구 | 검색 공간 | 특성 |
|------|-----------|------|
| `search_law` | 240,695건 | 조문 제목이 강력한 매칭 단서 → **Recall 0.90** |
| `search_precedent` | 579,012건 | 수많은 유사 판례 중 특정 1건 찾기 → **Recall 0.40** |
| `search_constitutional_decision` | 99,394건 | 수많은 유사 결정 중 특정 1건 찾기 → **Recall 0.36** |

법령 검색은 조문 제목이라는 구조화된 메타데이터가 있어 검색이 효과적입니다. 반면 판례/결정례는 주제가 유사한 문서가 매우 많아 특정 문서를 top-5에 포함시키기 어렵습니다.

**실사용에서의 의미**: 사용자가 "과잉금지원칙 관련 판례"를 검색하면 시스템은 과잉금지원칙에 관한 판례를 반환하지만, 그것이 교과서가 대표로 꼽는 바로 그 판례인지는 보장하지 않습니다. 다만 RAG 시나리오에서 LLM(Claude Pro)은 반환된 관련 판례를 기반으로 충분히 유용한 답변을 생성할 수 있습니다.

## 9. 한계 및 향후 개선

### 9.1 평가셋의 한계

- 법령 검색 40건은 7개 법령에 집중되어 있음. 5,500+ 법령 전체를 대표하지는 않음
- 법령해석례 8건은 정답을 비워두고 메타데이터 무결성만 측정하여 Recall에 기여하지 않음
- 판례/결정례의 "정답"은 교과서 대표 판례 1건이지만, 실무적으로는 관련 판례가 반환되면 충분할 수 있음

### 9.2 확인된 약점

- **헌법 조문 검색**: 대한민국헌법은 조문 제목이 없어, 개념 검색 시 같은 키워드를 제목에 포함한 다른 법률이 우선 매칭됨
- **동의어 불일치**: "재결의 종류" vs "재결의 구분" 같은 유의어 차이를 아직 커버하지 못하는 경우 있음
- **판례/결정례 의미 검색**: 579K/99K 규모의 컬렉션에서 특정 1건을 의미 검색으로 top-5에 포함시키기 어려움

### 9.3 개선 방향

1. **헌법 조문 제목 메타데이터 추가**: 제11조 → "평등권/평등의 원칙" 등 인위적 제목 부여
2. **동의어 사전 확장**: "종류"↔"구분", "규정"↔"조항" 등
3. **판례 검색 전략 개선**: 판시사항/판결요지 섹션에 가중치를 부여하거나, 대표 판례 부스팅
4. **top_k 확대 평가**: top_k=10, 20으로 늘렸을 때 Recall 변화 측정
5. **평가셋 다변화**: 5,500+ 법령 중 더 다양한 법령의 조문 포함
